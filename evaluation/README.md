# JobCopilot Evaluation

JobCopilot is evaluated as a system, not only demonstrated through a successful prompt.

## Benchmark V1

Benchmark V1 is a frozen, synthetic and human-authored evaluation suite. It avoids redistributing copyrighted job advertisements or private candidate data.

It contains:

- `job_offers.v1.jsonl`: 50 annotated offers across 10 role families;
- `retrieval_cases.v1.jsonl`: 20 profile-memory relevance judgments;
- `grounding_cases.v1.jsonl`: 20 isolated candidate claims labeled `supported`, `unsupported` or `ambiguous`;
- `email_grounding_review.example.jsonl`: the format for reviewing claims from emails actually generated by JobCopilot.

The 10 offer families are LLM applications, machine learning, data engineering, MLOps, computer vision, information retrieval, responsible AI, analytics, cloud AI and applied research.

## Integrity validation

The CI validates that:

- the extraction dataset contains exactly 50 unique offers;
- all expected schema fields are present;
- at least 10 role categories are represented;
- retrieval and grounding cases reference valid public-demo memory IDs;
- all grounding labels are valid and all three classes are represented.

Run locally:

```bash
python scripts/validate_benchmark.py
```

## 1. Structured extraction evaluation

Run a low-cost smoke evaluation first:

```bash
python scripts/evaluate_job_extraction.py --limit 5
```

Run the full frozen dataset:

```bash
python scripts/evaluate_job_extraction.py
```

This requires a configured Anthropic API key.

Reported outputs include:

- normalized exact accuracy for company, role, location, contract type and start date;
- precision, recall and F1 for list-valued fields;
- macro-average list F1;
- aggregate scores and slices by language, category and difficulty when those fields are present;
- per-case predictions for error analysis;
- model name, benchmark version, dataset hash, prompt hash and timestamp.

## 2. Profile-memory retrieval evaluation

```bash
python scripts/evaluate_retrieval.py \
  --dataset evaluation/retrieval_cases.v1.jsonl \
  --output evaluation/results/retrieval_report.json
```

Reported metrics:

- Recall@1, Recall@3 and Recall@5;
- MRR;
- NDCG@1, NDCG@3 and NDCG@5;
- ranked memory IDs for case-level analysis.

The first run may download the configured sentence-transformer model.

## 3. Static grounding-label benchmark

`grounding_cases.v1.jsonl` evaluates whether a model or reviewer can classify isolated candidate claims against specified evidence.

A prediction file contains one object per case:

```json
{"id": "ground_001", "label": "supported"}
```

Score it with:

```bash
python scripts/evaluate_grounding.py \
  --predictions evaluation/results/grounding_predictions.jsonl
```

Reported metrics:

- accuracy;
- macro F1;
- precision, recall and F1 by label;
- gold label distribution.

This task measures grounding-label classification. It does **not** by itself measure the unsupported-claim rate of emails generated by JobCopilot.

## 4. Generated-email grounding review

Generate JobCopilot outputs and prepare them for human review:

```bash
python scripts/prepare_email_grounding_review.py --limit 10
```

Use `--limit 0` for all 50 offers. The output includes:

- the generated subject and email body;
- the exact candidate memories retrieved for that offer;
- an empty `claims` list for human annotation.

The reviewer splits each email into factual candidate claims and assigns:

- `supported`: directly supported by one or more retrieved memories;
- `unsupported`: unsupported or contradicted by the retrieved evidence;
- `ambiguous`: related evidence exists but is too weak to verify the claim.

Supported and ambiguous claims must list retrieved memory IDs. Unsupported claims must list no evidence IDs.

After annotation, compute the real generated-email unsupported-claim rate:

```bash
python scripts/summarize_email_grounding_review.py \
  --annotations evaluation/results/email_grounding_review.jsonl
```

Reported metrics:

- supported rate;
- unsupported claim rate;
- ambiguous rate;
- claim counts and per-job unsupported-claim rates.

`email_grounding_review.example.jsonl` demonstrates the completed annotation format only. Its numbers are not JobCopilot performance results.

## Versioning and reporting rules

Every empirical report should record:

- dataset version;
- model name;
- prompt version or commit SHA;
- run timestamp;
- number of cases successfully processed;
- failed or retried API calls;
- aggregate metrics and per-case outputs.

## Interpretation boundary

Benchmark V1 is synthetic and manually authored by the project owner. It is useful for regression testing, comparative experiments and portfolio evidence, but it is **not production-accuracy evidence** and must not be described as representative of the full job market.

A stronger V2 should add independently annotated real-world offers whose licensing permits redistribution, inter-annotator agreement, multilingual adversarial cases and repeated runs across several models.
